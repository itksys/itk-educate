LESSON 3

IT業界の職種

1つのアプリやシステムは、1人のスーパーエンジニアが作っているわけではありません。 役割の違うたくさんの人が分担して作っています。 このレッスンでは、IT業界の主な職種と、それぞれが何をしているのかを整理します。

IT業界の名刺は、とにかくカタカナが長いです。「シニア・バックエンド・エンジニア」「クラウド・インフラ・アーキテクト」…… 初めて見ると、ちょっとした早口言葉です。

でも安心してください。分解してみると、「どの部分を」「どの立場で」担当しているかを言っているだけ。 このレッスンを読み終わるころには、名刺を見ただけで「この人はこういう仕事をしているんだな」とわかるようになります。

1. 家づくりで考える全体像

システム開発は、よく家づくりにたとえられます。家を建てるときも、設計する人・工事をする人・内装を考える人など、 たくさんの専門家が関わりますよね。IT の職種も、ほぼ同じように対応させることができます。

家づくりでいうとIT の職種ひとことで言うと
施主（家を建てたい人）お客様「こんなシステムがほしい」と依頼する
現場監督プロジェクトマネージャー（PM）予算・スケジュール・メンバーを管理する
建築士（設計士）システムエンジニア（SE）お客様の要望を聞いて、設計図を書く
大工さんプログラマー（PG）設計図をもとに、実際に作る
インテリアデザイナーデザイナー見た目と使い心地を考える
内装工事の職人フロントエンドエンジニアデザインを、実際に触れる画面に仕上げる
水道・電気・ガスの設備工事バックエンドエンジニア見えないけれど、ないと暮らせない仕組みを作る
収納・倉庫の設計DBエンジニア大切なデータを、整理してしまっておく
土地の造成・基礎工事・電線や水道管の引き込みインフラエンジニアシステムが建つ土台を用意し、守る
完成検査の検査員テスター / テストエンジニア引き渡し前に、不具合がないかを徹底的に確かめる

2. 職種は「2つの軸」で見るとわかりやすい

IT の職種名には、実は2種類の分け方が混ざっています。ここを押さえると、職種名がぐっと読み解きやすくなります。

① どの「立場」で関わるか（縦の軸）

プロジェクトの中での役割です。PM・SE・PG がこちら。「管理する」「設計する」「作る」の違いです。

② どの「部分」を担当するか（横の軸）

システムのどこを専門にするかです。フロントエンド・バックエンド・DB・インフラがこちら。Lesson 2 で学んだ各部分に対応します。

たとえば「バックエンドの SE」なら「サーバー側の処理を設計する人」、 「インフラの SE」なら「サーバーやネットワークの構成を設計する人」です。 なお、デザイナーはこの表とは別に、画面の見た目と使いやすさを専門に担当します。 実際の現場では、1人が複数のマスを担当することもよくあります。

ポイント： 名刺の「シニア・バックエンド・エンジニア」を分解すると、 「シニア（経験豊富な）」＋「バックエンド（横の軸）」＋「エンジニア（技術者）」。 カタカナが長くても、軸に当てはめれば怖くありません。

3. SE と PG の違い

IT 業界でよく聞く SE（システムエンジニア）と PG（プログラマー）。 どちらも「エンジニア」ですが、担当する工程（仕事の段階）が違います。

SE（システムエンジニア）＝「何を・どう作るか」を決める人

  • お客様の要望を聞き取って整理する（要件定義）
  • システムの全体像や画面・機能を決める（基本設計）
  • プログラムの細かい作りを決める（詳細設計）
  • 設計書を作り、PG に作業を依頼する
  • 出来上がったものが要望どおりか確かめる（テスト）

PG（プログラマー）＝ 設計をもとに「実際に作る」人

  • 設計書を読み、プログラムを書く（実装・コーディング）
  • 書いたプログラムが正しく動くか確かめる（単体テスト）
  • 見つかった不具合（バグ）を直す
  • より良い作り方があれば SE に提案する

レストランにたとえると

SE はお客様の注文を聞いてメニューとレシピを考えるシェフ、PG はレシピどおりに手際よく料理を仕上げる料理人です。 どちらが欠けても、おいしい料理は出せません。

実際の現場では： SE と PG がはっきり分かれているのは、大規模なシステムを作る会社に多い形です。 Web サービスの会社などでは、設計もプログラミングも同じ人が担当し、まとめて「エンジニア」と呼ぶことが増えています。 また、PG として経験を積んでから SE になる、というキャリアの進み方も一般的です。

4. 各職種の役割

ここからは、主な職種を1つずつ見ていきましょう。

まとめる・決める人

プロジェクトマネージャー

Project Manager（PM）

プロジェクトを最後までゴールに導く「現場監督」

主な仕事
  • 計画を立てる（いつまでに・誰が・何を作るか）
  • 予算・スケジュール・品質の管理
  • メンバー集めと役割分担
  • お客様との調整、トラブルへの対応
よく使う道具
Excel（スケジュール表）、ガントチャート、Backlog や Jira などのタスク管理ツール
向いている人
全体を見渡すのが好き、人と話して調整するのが得意な人
家づくりでいうと 現場監督。自分で釘は打たなくても、家が予定どおり完成するかは監督次第。

システムエンジニア

System Engineer（SE）

お客様の「こうしたい」を設計図に落とし込む人

主な仕事
  • お客様へのヒアリング、要件定義
  • 基本設計・詳細設計、設計書の作成
  • テストの計画と確認
  • PG への作業依頼と質問対応
よく使う道具
Excel・Word（設計書）、PowerPoint（提案資料）、図を描くツール
向いている人
話を聞いて整理するのが得意、論理的に考えるのが好きな人
家づくりでいうと 建築士。施主の「広いリビングがほしい」を、柱の位置まで決めた図面にする。

プログラマー

Programmer（PG）

設計図をもとに、実際に動くプログラムを作る人

主な仕事
  • プログラミング（コーディング）
  • 単体テスト、バグの修正
  • コードレビュー（他の人のプログラムの確認）
よく使う道具
エディタ（VS Code など）、Git（変更履歴の管理）、各種プログラミング言語
向いている人
ものづくりが好き、コツコツ試行錯誤するのが苦にならない人
家づくりでいうと 大工さん。図面どおりに、しっかりした家を組み上げる。

見た目と使いやすさを作る人

デザイナー（UI / UX デザイナー）

Designer

「見やすい」「迷わない」「気持ちいい」を設計する人

主な仕事
  • 画面のレイアウト・配色・アイコンのデザイン
  • 操作の流れ（どの順にボタンを押すか）の設計
  • ユーザーの声を聞いて改善する
よく使う道具
Figma、Adobe Illustrator / Photoshop
向いている人
使う人の気持ちを想像するのが得意、見た目のこだわりがある人
家づくりでいうと インテリアデザイナー。 UI は「画面の見た目や操作部分」、UX は「使ったときの体験全体」のこと。

フロントエンドエンジニア

Frontend Engineer

デザインを、実際に触って動く画面にする人

主な仕事
  • デザインをもとに画面を作る（コーディング）
  • パソコン・スマホなど、どの画面サイズでも崩れないよう調整
  • バックエンドからデータを受け取って表示する
主な技術
HTML、CSS、JavaScript / TypeScript、React、Vue.js
向いている人
目に見える成果が好き、細かい見た目のズレが気になる人
家づくりでいうと 内装工事の職人。デザイン画を、実際に住める部屋に仕上げる。（→ Lesson 1 Webアプリ）

裏側と土台を作る人

バックエンドエンジニア

Backend Engineer

画面の裏で動く「仕組み」を作る人

主な仕事
  • ログイン・注文・決済など、サーバー側の処理を作る
  • 画面やスマホアプリとやりとりする窓口（API）を作る
  • データベースへの保存・読み出しの処理を作る
主な技術
Java、PHP、Python、Go、Node.js、C#、SQL
向いている人
仕組みを考えるのが好き、正確さにこだわれる人
家づくりでいうと 水道・電気・ガスの設備工事。普段は見えないけれど、止まったら生活できない。（→ Lesson 2 サーバーの中身）

DBエンジニア

Database Engineer

会社の宝物である「データ」を守り、使いやすく整える人

主な仕事
  • どんなデータを、どんな表（テーブル）で持つかを設計
  • データが増えても検索が遅くならないよう調整（チューニング）
  • バックアップや、データが消えたときの復旧
主な技術
SQL、MySQL、PostgreSQL、Oracle Database、SQL Server
向いている人
整理整頓が好き、慎重に物事を進められる人
家づくりでいうと 収納・倉庫の設計。何をどこにしまえば、すぐ取り出せて失くさないかを考える。

インフラエンジニア

Infrastructure Engineer

システムが動く「土台」を用意し、止まらないように守る人

主な仕事
  • サーバー・ネットワーク・クラウド環境の設計と構築
  • システムが止まっていないかの監視、障害時の対応
  • 不正アクセスなどへのセキュリティ対策
主な技術
AWS・Azure などのクラウド、Linux、ネットワーク機器（ルータ・スイッチ）
向いている人
縁の下の力持ちタイプ、トラブル時も落ち着いて原因を探せる人
家づくりでいうと 土地の造成・基礎工事・電線や水道管の引き込み。 担当によって「サーバーエンジニア」「ネットワークエンジニア」「クラウドエンジニア」とも呼ばれる。（→ Lesson 2 OSI参照モデル）

品質を守る人

テスター / テストエンジニア

Tester / Test Engineer

「ちゃんと動く？」を徹底的に確かめる、最後の砦

主な仕事
  • 何を・どんな手順で確かめるかを決める（テスト設計、テストケースの作成）
  • 実際にシステムを操作して、結果が正しいかを確認する（テスト実施）
  • 見つけた不具合を、再現手順つきで開発者に報告する
  • 修正されたあと、本当に直ったか・他が壊れていないかを再確認する
よく使う道具
Excel（テストケース表）、不具合管理ツール（Backlog・Jira など）、テストを自動で実行するツール
向いている人
細かいところに気がつく、「こう操作したらどうなる？」と試したくなる人
家づくりでいうと 完成検査の検査員。ドアは閉まる？ 水は漏れない？ を引き渡し前に1つずつ確かめる。

テスターとテストエンジニアの違い

SE と PG の関係に似ています

テストエンジニア
「どんなテストをすれば不具合を見つけられるか」を考え、テストの計画やテストケースを作る人。
テスター
テストケースに沿って実際にシステムを操作し、結果を確認・記録する人。
QA エンジニア
テストだけでなく、開発の進め方も含めて「品質を保証する仕組み」づくりまで担当する人。QA は Quality Assurance（品質保証）の略。
「エンジニアが自分でテストすればいいのでは？」と思うかもしれません。でも、作った本人はどうしても 「正しい使い方」で試してしまいがち。作った人とは別の目で確かめることで、思わぬ不具合が見つかります。

7. キャリアの広がり

職種は固定されたものではありません。経験を積みながら、いろいろな方向に進めます。

マネジメントの道

PG → SE → PL → PM のように、作る人から「まとめる人」へ進む道。日本の IT 企業では昔からよくある流れです。

スペシャリストの道

フロントエンド、インフラ、DB、セキュリティなど、1つの分野を深く極める道。「その分野ならあの人」と頼られる存在になります。

横に広げる道

フロントもバックも両方できる「フルスタックエンジニア」や、技術がわかる営業・コンサルタントなど、得意分野を組み合わせる道。

確認クイズ

次の仕事をしているのは、どの職種でしょう？ 選択肢をクリックしてください。

Q1. お客様と打ち合わせをして要望を整理し、システムの設計書を書く

Q2. 設計書をもとにプログラムを書き、正しく動くかテストする

Q3. プロジェクトのスケジュールと予算を管理し、遅れそうならメンバーの配置を見直す

Q4. ユーザーが迷わず使えるよう、ボタンの配置や配色、操作の流れを考える

Q5. 夜中にシステムが止まったという連絡を受け、サーバーやネットワークの状態を調べる

Q6. 会員データが100万件に増えても検索が遅くならないよう、データの持ち方を見直す

Q7. ネットショップで「購入する」ボタンを押したあとの、注文登録や決済の処理を作る

Q8. リリース前に、決められた手順どおりにシステムを操作し、おかしな動きがないか確かめて報告する

まとめ

  • システムは、役割の違うたくさんの人の分担で作られている（家づくりと同じ）。
  • 職種名は、どの「立場」で関わるか（PM・SE・PG）と、どの「部分」を担当するか（フロント・バック・DB・インフラ）の2つの軸で読み解ける。
  • SE は「何を・どう作るか」を決める人、PG は設計をもとに「実際に作る」人。
  • デザイナーは見た目と使いやすさを、インフラエンジニアはシステムの土台を、テスターは品質の確認を担当する。
  • 営業や管理部門も含めて、みんながチームの一員。
